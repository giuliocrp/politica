# Data Sources

Canonical reference for every dataset `Politici` ships. **This file must
match `Politici/Data/sources.json` (and therefore the in-app "Informazioni
e fonti" screen) exactly** — `sources.json` is generated by
`tools/make_manifest.py`, not hand-edited, so it's the authoritative
source of truth; this file restates it in a more browsable form and adds
the transformation detail the in-app screen has no room for. If the two
ever disagree, `sources.json` is right and this file is stale — regenerate
it or fix this file, don't just trust whichever you're looking at.

Cross-checked against the shipping `Politici/Data/sources.json` on
2026-07-22 (v4 Phase 25, when the two plurinominale boundary sources were
added — originally cross-checked with 5 entries on 2026-07-18, 6 in v3 Phase
16): **all 8 entries match exactly** (id, name, url, license, retrievedAt,
notes) — see "Cross-check" at the bottom for the verification method.

URLs (`?foto`) exist in the source but are **not** carried into the app —
see the README's "Known limitations."

## Camera dei Deputati — Votazioni (XIX Legislatura)

| | |
|---|---|
| **Portal** | [dati.camera.it](https://dati.camera.it/) |
| **Dataset** | Votazioni (roll-call votes) — XIX Legislatura |
| **Access method** | SPARQL endpoint, `https://dati.camera.it/sparql` |
| **License** | CC BY 4.0 — verified at [creativecommons.org/licenses/by/4.0](https://creativecommons.org/licenses/by/4.0/) |
| **Retrieved** | 2026-07-18 |
| **Queries** | `tools/queries/camera_votazioni_scope.rq` + `camera_votazioni_dettaglio.rq` (pinned, versioned) |
| **Fetch script** | `tools/fetch_camera_votes.py` → `tools/raw/camera_votazioni_sparql.json` (gitignored cache) |
| **Import script** | `tools/import_votes.py`, scoped by `tools/config/votes_scope.json` |

**Transformation summary**: scoped to Assemblea, non-secret ("electronic")
roll-call votes of the XIX legislature, ordered by date descending. Secret
ballots are excluded by design — their per-deputy records only carry a
generic `"Ha votato"` (voted) flag, never a disclosed position, so
including them would misrepresent inherent unattributability as missing
data. The nominal scope is the 25 most recent qualifying votes; a
`maxPositionRecords` bundle-size budget (5,000 records, tuned to land
under a ~2MB `Data/votes.json`) actually capped the import at **12 votes,
4,788 per-deputy positions** — the pipeline stops at the first vote that
would exceed budget rather than silently truncating within a vote. Raw
position vocabulary (`"Favorevole"`/`"Contrario"`/`"Astensione"`/`"Non ha
votato"`) is mapped explicitly onto the app's `VoteChoice` enum (note:
`"Astensione"` → `.astenuto`, a noun→adjective translation, and `"Non ha
votato"` → `.assente`, the closest existing case for "no favorevole/
contrario/astensione recorded" — see
[`docs/v2/04-votes-import.md`](v2/04-votes-import.md) for the full observed
vocabulary and every mapping decision). `sourceUrl` is the real, verbatim
`dc:relation` deep link to the vote's official "scheda votazione" page —
never constructed.

excludes 7 senators whose mandate has ended (4 deceased, 2 resigned, plus
former President Giorgio Napolitano — life senator by right, but deceased

senators whose `osr:tipoElezione` starts with `"Eletto uninominale"` carry

`osr:collegioElezione` against the ISTAT Senato boundaries (parse rule and
the single Valle d'Aosta naming alias documented in

[`docs/v3/17-senato-mandates.md`](v3/17-senato-mandates.md)).
`electionType` stays null for senators — `tipoElezione` is consumed at
import time for linkage eligibility only.

| **Portal** | [istat.it](https://www.istat.it/notizia/le-basi-geografiche-dei-nuovi-collegi-elettorali-2) |
| **Dataset** | Basi geografiche dei collegi elettorali, Camera dei Deputati — collegi uninominali (D.Lgs. 177/2020) |
| **Access method** | Shapefile download (manual — not SPARQL; see `tools/raw/SOURCES.txt` for the exact download reference) |

**Transformation summary**: source shapefile is EPSG:32632 (WGS 84 / UTM

`CU20_DEN`'s `"{circoscrizione} - {subCode}"` structure — verified against
all 147 rows with zero exceptions, and cross-checked against the official

[`docs/v2/03-linkage-report.md`](v2/03-linkage-report.md)). This dataset
covers **Camera uninominali only** — the Senato uninominali, and both
chambers' plurinominali, are documented as their own separate sources below
(Senato uninominali added in v3 Phase 16; both plurinominali in v4 Phase
25).

## ISTAT — Basi geografiche dei collegi elettorali (Senato, uninominali)

| | |
|---|---|
| **Portal** | [istat.it](https://www.istat.it/notizia/le-basi-geografiche-dei-nuovi-collegi-elettorali-2) |
| **Dataset** | Basi geografiche dei collegi elettorali, Senato della Repubblica — collegi uninominali (D.Lgs. 177/2020) |
| **Access method** | Shapefile download (manual — not SPARQL; same release as the Camera entry above, downloaded in the same batch — see `tools/SOURCES.md`) |
| **License** | CC BY 4.0 — verified at [creativecommons.org/licenses/by/4.0](https://creativecommons.org/licenses/by/4.0/) |
| **Retrieved** | 2026-07-18 (same download event as the Camera ISTAT entry — one manual `tools/raw/collegi/` acquisition covered both layers) |
| **Build script** | `tools/build_boundaries.sh senato` (`ogr2ogr` reprojection + simplification) → `tools/import_boundaries.py --chamber senato` |

**Transformation summary** (v3 Phase 16; exploration in
[`docs/v3/15-senato-exploration.md`](v3/15-senato-exploration.md), full
measurements in [`docs/v3/16-senato-boundaries.md`](v3/16-senato-boundaries.md)):
source shapefile is EPSG:32632, same CRS as Camera's; reprojected to
EPSG:4326 and simplified at the same 1000m tolerance as Camera (measured
to clear both the byte and per-feature-vertex gates with wide margin, no
retuning needed) — **74 features, ~847KB, 34 of them `MultiPolygon`**. `id`
= `"S"` + `SU20_COD` (cast to string) — the plain numeric code collides
with 32 of the 147 Camera ids, so the `"S"` prefix is applied
unconditionally to every Senato id, never just the colliding ones; Camera
ids are never modified. `name` = `SU20_DEN`; `subCode` is derived the same
way as Camera's. **`regione`** (not `circoscrizione`) is derived by
parsing `SU20_DEN`'s `"{regione} - {subCode}"` structure: Senato's
grouping is one of Italy's 20 *unsplit* administrative regions, a
genuinely different concept from Camera's 28 circoscrizioni (which split
several larger regions into multiple electoral groupings) — reusing
`circoscrizione` for Senato would misrepresent that structural difference,
so Senato features carry `regione` and leave `circoscrizione` absent, and
vice versa for Camera. **No senator-to-collegio linkage exists** — Phase
15's source exploration found no collegio-shaped predicate anywhere in the
Senato SPARQL cache; every senator's `districtId` stays `null` regardless
of this boundaries source (see the Senato Open Data entry above and
`docs/v3/15-senato-exploration.md`'s GO/NO-GO(LINK) finding).

## Data-refresh procedure

To pull fresh data from all live sources and regenerate every `Data/*`
file (except boundaries, which come from a manually-downloaded shapefile,
not a SPARQL endpoint — see step 3):

1. **`make fetch`** — the only network-touching step. Runs every pinned
   `.rq` query in `tools/queries/` against the live Camera/Senato SPARQL
   endpoints, writes raw responses to `tools/raw/*.json` (gitignored,
   regenerable, never committed), and stamps
   `tools/raw/.fetch_metadata.json` with today's date per source.
2. **`make import`** — offline. Merges `tools/raw/*.json` into
   `Data/representatives.json` and `Data/votes.json`. Fails loudly (no
   output written) if the raw cache is missing or referential integrity
   would break (e.g. a vote referencing a deputy not in
   `representatives.json`).
3. **`make boundaries`** / **`make boundaries-senato`** — offline, only
   needed if the ISTAT shapefile itself changed (re-download it manually
   into `tools/raw/collegi/CAMERA_CollegiUNINOMINALI_2020/` /
   `tools/raw/collegi/SENATO_CollegiUNINOMINALI_2020/` first — neither step
   fetches it). Rebuild `Data/districts.geojson` / `Data/districts_senato.geojson`
   respectively.
4. **`make validate`** — offline. Re-checks every file's structure and
   cross-references from scratch (not trusting that import already got it
   right), including cross-file id uniqueness between the two boundary
   files — exits non-zero with a specific diagnostic on any violation.
5. **`make manifest`** — offline. Regenerates `Data/sources.json` from the
   real fetch timestamps in `.fetch_metadata.json` (not "whenever this
   script happens to run"). **After this step, re-verify this file
   (`docs/DATA_SOURCES.md`) still matches `Data/sources.json`** — the
   `retrievedAt` dates above will need updating; nothing does that
   automatically.

Shorthand for steps 1–2 + 4–5 in one line (boundaries excluded, since it
needs a manual shapefile re-download first): `make fetch && make import
&& make validate && make manifest` — or use `make refresh` (fetch, then
the fully offline `make all`, which runs `make boundaries` and `make
boundaries-senato` too — both safe to run even without a shapefile
update; they're idempotent against the same source files).
